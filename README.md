# 休日・夜間 医療機関ナビ

川崎市内で、休日や夜間に診療予定が登録されている医療機関を探すための簡易プロトタイプです。地域（区）・曜日または祝日・時刻・診療科コードを指定して検索し、一致した施設と登録時間を表示します。

データ基準日は**2026年6月1日**です。検索結果は公開データ上の登録内容を示すもので、当日の診療実施や患者の受入状況を保証しません。

## 開発背景

休日や夜間に医療機関を探す際、希望する地域・診療科・時間に合う施設を見つけるため複数の情報を確認する手間があります。一方、登録された診療時間と当日の診療状況・受入可否は一致するとは限りません。

本プロトタイプでは、まず公開データの診療予定を検索条件で絞り込めるところまでを実装しました。診療時間と休診フラグの不一致など、データの注意点も結果に表示します。診断、緊急度判定、実際の受診先の決定は行いません。

## 既存サービスとの関係

機能の優劣を示す比較ではなく、今回の実装範囲とデータの違いを整理しています。Google検索・Googleマップ、ChatGPTの現行機能を網羅的に調査したものではありません。

| サービス・方式 | 今回のプロトタイプとの関係 |
|---|---|
| ChatGPTなどの生成AI | このアプリは自由文を解釈せず、4つの選択条件と診療科コードで検索します。LLMは組み込んでいません。生成AIで可能な検索・回答との機能比較は行っていません。 |
| Google検索・Googleマップ | このアプリは地図、経路、位置情報による検索を実装していません。厚生労働省の固定時点データを区・曜日・時刻・診療科で絞る範囲に限定しています。既存サービスに同様の機能がないとは主張しません。 |
| 厚生労働省「医療情報ネット」 | 本アプリが利用するデータの出典です。医療情報ネットは全国の医療機関等をさまざまな条件で検索できる公式サービスです。本アプリは川崎市の病院・診療所と限られた検索項目を扱う簡易プロトタイプで、公式サービスを置き換えるものではありません。 |

今回確認したデータでは、休診フラグが「休診」でありながら診療時間の登録がある施設が見つかりました。施設単位のフラグと診療科・時間帯単位の予定では意味の範囲が異なる可能性があり、ただちに誤りとは判断できません。このアプリでは不一致を理由に施設を自動除外せず、注意事項として表示します。これはデータ品質の見える化に向けた基礎であり、他サービスに同様の表示がないという比較結果ではありません。

## 使用するオープンデータ

厚生労働省「医療情報ネット」の**2026年6月1日時点**の公開データを使用します。

- 病院（施設票）
- 病院（診療科・診療時間票）
- 診療所（施設票）
- 診療所（診療科・診療時間票）
- オープンデータ定義書（項目確認用）

前処理の対象は川崎市内の**病院38施設、診療所886施設**です。施設票・診療時間票は`ID`で関連付けます。入力CSVはUTF-8 BOM付きで、ID・地域コード・診療科コードは文字列のまま扱います。定義書は項目とコードの確認に使い、前処理コマンドが読み込む入力は4つのCSVです。

出典： [厚生労働省「医療情報ネットのオープンデータ」](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/kenkou_iryou/iryou/newpage_43373.html)。同ページ記載の**公共データ利用規約（PDL1.0）および利用条件**に従ってください。掲載情報は医療機関等から報告された内容で、最新でない情報や報告内容の誤りが含まれる場合があると案内されています。アプリの検索結果もこの制約を引き継ぎます。

## 実装済みの機能

- 川崎市7区、月曜日〜日曜日または祝日、時刻、診療科コードによるAND検索
- 診療科・曜日・時間帯ごとの登録を保持した検索
- 施設IDによる検索結果の重複排除
- 一致した診療科名と登録時間帯の表示
- 休診フラグとの不一致・空欄・特定週情報に関する注意表示
- 施設種別、名称、所在地、区、データ基準日の表示
- Streamlit画面での検索用インデックスと診療科一覧のキャッシュ
- 検索処理・前処理のpytest（20件）

診療科の検索キーはデータ上のコードです。同じコードに複数の名称がある場合、名称を統合せず、コードに紐づく名称を画面に表示して検索します。「内科」と「循環器内科」など別コードの診療科をまとめません。

## 技術・設計

- **Python**：CSVの前処理と検索処理
- **標準ライブラリ`csv`**：大きな入力CSVをストリーム処理し、コードや先頭ゼロを文字列として保持
- **Streamlit**：検索条件と結果を表示する1画面のUI
- **pytest**：検索境界、複数時間帯、重複排除、欠損・特殊時刻、休診情報の注意を確認

前処理・検索・画面を分離しています。前処理は`medical_hours_navi/preprocessing.py`、検索は`medical_hours_navi/search.py`、UIは`app.py`です。短期間のローカルMVPとして、既存CSVを直接使える構成にし、APIサーバー、RAG、FAISS、データベースは導入していません。前処理と検索はLLMに依存しません。

前処理で生成する検索用ファイルは次の3つです。

- `data/processed/facilities.csv`：施設情報
- `data/processed/consultation_hours.csv`：診療科・曜日・時間帯ごとの診療時間
- `data/processed/closure_flags.csv`：通常曜日・祝日・第1〜第5週の休診フラグ

## 時刻・休診情報の扱い

時刻は`HH:MM`（00:00〜23:59）として検証します。開始＜終了の枠のみを検索対象とし、`開始時刻 <= 検索時刻 < 終了時刻`で判定します。この境界条件は公式規則ではなく、MVP用の仮ルールです。

開始＞終了、開始＝終了、時刻の欠損・形式不正は元の値と除外理由を保持して検索対象外にします。両端が空欄の枠は出力せず、件数を処理ログに記録します。時間帯1〜3は独立した枠として保持します。日跨ぎや開始＝終了の意味を補完しません。

休診フラグは`0`（休診）、`1`（診療）、空欄（未確認）を保持します。フラグと時間の優先関係は未確定のため、矛盾があっても検索結果から自動除外しません。特定週情報がある施設には、実際の日付による確認が必要と表示します。

## AI活用の方針

現時点でAI機能は実装していません。時刻や診療科の検索は、構造化された公開データを既定のPythonロジックで照合します。

将来の検討案：

1. **自然言語検索**：文章から地域・日付・時刻・診療科の候補を抽出し、利用者が確認してから既存検索に渡す。
2. **非構造化情報の整理**：自治体のWeb/PDFや医療機関公式サイトにある休日診療・臨時休診情報を抽出し、出典と取得時点を付けて構造化する。
3. **情報源の照合**：公開データと他の公式情報の差分を提示し、人が確認できるようにする。

AIが医療機関名や診療時間を推測で補う設計にはしません。抽出結果は原文・出典と照合し、未確認の情報は検索一致として扱わない方針です。

## 制約と今後の改善

### 現在の制約

- 登録された診療予定の検索であり、当日の診療実施・患者の受入状況を保証しません。受診前に医療機関へ確認してください。緊急時は119番をご利用ください。
- データは2026年6月1日時点の固定スナップショットです。自動更新しません。
- 川崎市全域を一括指定する検索、日付に基づく特定週の完全な休診判定は未実装です。
- 0時をまたぐ枠、開始＝終了の枠は未解釈として検索対象外です。
- 電話番号、公式サイトリンク、地図・経路表示は未実装です。
- 医療診断や緊急度判定は行いません。

### 今後の改善案

- データ更新手順と基準日の管理
- 日付・祝日カレンダーを含む週別休診の判定
- 未解釈時間や休診フラグ不一致の品質レポート
- 公式サイト等との人手による照合手順と、確認日・出典の表示
- 利用者テストを踏まえた検索結果・注意表示の改善
- 前述のAI案は、検証可能な出典管理を整えた後に個別評価

## 起動方法・テスト

プロジェクトルートで仮想環境を有効にし、依存関係をインストールします。

```bash
source .medical-hours-navi/bin/activate
python -m pip install -r requirements.txt
```

加工済みデータがまだない場合：

```bash
python -m medical_hours_navi.preprocessing --data-dir data --output-dir data/processed
```

Streamlitアプリを起動します。

```bash
python -m streamlit run app.py
```

テスト：

```bash
pytest -q
```

現在のテストは20件です。検索・前処理のテストは成功しています。Streamlitの`AppTest`では画面の描画と指定された3検索例（51件、1件と特定週注意、0件）を確認し、例外はありませんでした。一方、このCodex実行環境ではStreamlit HTTPサーバーのソケット待受がOS権限エラーとなるため、ブラウザでの実起動・再起動は確認できていません。画面表示や再起動を開発者環境で確認した場合は、提出前にその実施結果を別途記録してください。
